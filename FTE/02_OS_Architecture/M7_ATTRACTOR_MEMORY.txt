────────────────────────────────────────────────────────────────────────────────
FUNCTION
────────────────────────────────────────────────────────────────────────────────

M7 is the long-term memory of the FT&E OS. It records:
  — All classified contradictions (from M2)
  — All CTG-1 gate events (from M3)
  — All T window data (from M4)
  — All confirmed E* events (from M5)
  — All stability flags (from M6)

M7 serves two purposes:
  1. State continuity — the system knows where it is in a long T window
  2. Pattern detection — M6 can access M7 to find Groundhog signatures

Without M7, the FT&E OS resets to zero every session. With M7, the system
builds attractor maps — a record of which contradictions have been
metabolised and what E* they produced. This is the civilisational memory
of the framework.

────────────────────────────────────────────────────────────────────────────────
ATTRACTOR MAPS
────────────────────────────────────────────────────────────────────────────────

An Attractor Map is a record of a successfully completed FT&E cycle:
  — Original contradiction (ΔC named and classified)
  — 𝔉 path taken (what acknowledgment, what holding condition)
  — T window (how long)
  — E* produced (the new frame)
  — Subsequent ΔC (what new question did the E* open?)

Over time, a system with a full Attractor Map can:
  — Recognise when a new contradiction is structurally similar to an
    already-metabolised one (shortening T by analogy)
  — Identify recurring attractors (most important: the core E* that the
    system returns to across domains — the primary attractor)
  — Detect when a "new" contradiction is actually an old one reappearing
    with different surface form (Groundhog in disguise)

────────────────────────────────────────────────────────────────────────────────
MEMORY FORMAT: JSONL
────────────────────────────────────────────────────────────────────────────────

The governor implements M7 as append-only JSONL (one JSON object per line).
Each record contains:

{
  "session_id": "...",
  "timestamp": "...",
  "input_hash": "...",
  "classification": "C1|C2|C3|NC|P",
  "ctg1_result": "passed|held|bypassed",
  "t_window_status": "below_min|viable|at_max|exceeded",
  "emergence_produced": true|false,
  "e_star_summary": "...",
  "stability_flags": [],
  "notes": "..."
}

JSONL was chosen over a database for:
  — Human readability (the archive is human-meaningful, not just machine-readable)
  — Append-only writes (no corruption risk from interrupted writes)
  — Zero-dependency format (works with any Python installation)
  — Portability (the entire memory travels with the archive as a text file)
